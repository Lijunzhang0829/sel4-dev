# spec-strengthen

seL4 abstract-spec strengthening — detectors, executors, ledger,
and per-experiment audit dirs. Layout aligned with `lemma-staticize/`:
top-level entry script + `scripts/` (helpers) + `candidates/` (state) +
`experiments/` (output) + `surveys/` (markdown reports).

## Layout

```
spec-strengthen/
├── README.md                          this file
├── AInvs-spec-strengthen-summary.md   cross-batch narrative summary
├── run.sh                             ★ entry — orchestrator
│                                       (survey / execute / status / ledger / mark-audited)
├── scripts/                           reusable helpers — sourced/called by run.sh
│   ├── spec_frame_gap.py              Pattern G detector + dmo/dxo semantic gates
│   ├── spec_candidates.py             Pattern A / C detector
│   ├── spec_strengthen_scan.py        Hoare-triple parsing
│   ├── spec_op_args.py                op signature → arg names (used by execute_G)
│   ├── spec_impact.py                 impact verdict + measurement.json emitter
│   ├── spec_strengthen_c_patchgen.py  Pattern C patch generator
│   ├── spec_witness_gen.py            Pattern A / C `_old` witness generator
│   ├── spec_premise_probe.{sh,py}     Pattern C Isa-REPL probe (slow path — most C work
│   │                                  uses check-theory.sh --patch trial instead)
├── candidates/                        state machine
│   └── candidate-ledger.jsonl         append-only JSONL of all candidate events
├── experiments/                       per-expid audit dirs
│   └── <NNNN-tag>/
│       ├── decision.md                strict-strengthen claim + acceptance trace
│       ├── measurement.json           wall metrics + verdict
│       ├── patch.diff                 unified diff (canonical replay artifact)
│       ├── range-patch.patch.txt      check-theory.sh range-replace patch
│       └── command.sh                 re-runnable measurement script
├── surveys/                           per-file Tier-based survey markdowns
│   └── survey-<theory>-<date>.md
└── logs/                              (gitignored) ephemeral patches generated by run.sh
                                       — canonical copies live in experiments/<id>/range-patch.patch.txt
```

## Workflow

```bash
# 1. Scan a theory file for Tier 1 / 2 / 3 candidates
bash spec-strengthen/run.sh survey \
  verification/l4v/proof/invariant-abstract/<Theory>.thy --pattern G|C|A|all

# 2. Execute one candidate end-to-end (auto template + trial + apply + audit dir)
bash spec-strengthen/run.sh execute \
  --candidate '<key>' --expid <NNNN-tag> -y

# 3. Inspect / mark-audited / status
bash spec-strengthen/run.sh status [<key>]
bash spec-strengthen/run.sh ledger
bash spec-strengthen/run.sh mark-audited '<key>' --expid <NNNN-tag>
```

`run.sh` is just `scripts/spec_strengthen_run.sh` promoted to the top
level for clarity (lemma-staticize uses the same convention with
`bench.sh`). All `$SPEC_TOOLS` resolution inside it defaults to
`spec-strengthen/scripts/`.

## Pattern coverage

| Pattern | Detector | Execute path | Automation tier |
|---|---|---|---|
| **G** (frame lemma add) | `spec_frame_gap.py` + dmo/dxo semantic gates | `execute_G` (auto template via `spec_op_args.py`) | **fully auto** — 79% applied 0027-0034, 100% post-gates 0035-0053 |
| **C** (drop unused premise) | `spec_candidates.py --pattern C` | `execute_C` (probe + patchgen) | partially auto — most candidates load-bearing |
| **A** (paired weak/strong promotion) | `spec_candidates.py --pattern A` | `execute_custom --pattern A` (manual patch) | manual — modify-mode hits cascade (see [[0029]]) |
| **D** (loose-bound tightening) | manual | `execute_custom --pattern D` | manual |

## Design context

The **additive-unification** design (validated by PoC [[0054]])
proposes rewriting A / C / D as "add new lemma alongside the
original" instead of modification, eliminating the cascade class
of failures (see 0029 vs 0054 in their `decision.md` files).
Implementation deferred per scope agreement — the current layout
supports both modify-mode and additive-mode via existing
`execute_custom`; no code changes required to start adopting
additive shapes.

## Acceptance gates

Every experiment must pass all four gates before `applied`
verdict is recorded:

1. `check-theory.sh --patch` returns OK (Isabelle/HOL verifies)
2. `spec_impact.py` verdict is `additive` (no weakening detected)
3. Trial wall ≤ baseline × 1.30
4. Parent `isabelle_prover_spec` SKILL hard rules satisfied

## Ledger event types

- `discovered` — candidate surfaced by detector, no execute yet
- `preflight_failed` — mechanical gate rejected (direct / crunch / dmo / dxo)
- `probe_failed` — Pattern C probe found premise load-bearing
- `trial_failed` — check-theory.sh --patch did not return OK
- `impact_failed` — spec_impact verdict ≠ additive
- `applied` — full pipeline succeeded
- `audited` — author marked the audit dir as committed-and-reviewed
- `aborted` — explicitly removed from active consideration
