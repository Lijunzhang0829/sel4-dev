# 实验存储去重：第一阶段

## 已接入生产代码

`batch_target_memory[target]` 从完整 attempt 改为 `{"attempt_ref": SHA256}`；
`batch_attempt_objects` 在当前状态内保存每份不同 attempt 一次。摘要与恢复通过
`target_attempts` 解析，引用缺失或哈希不匹配立即报错。旧内联格式仍可读取。
对象更新采用新的内容身份，重算目标引用；当前状态不保留无引用的 attempt 对象，
历史请求和权威提交仍保留原有记录。这里没有删除任何已有实验文件。

恢复对 accepted/checked_not_committed 的修正发生在重新计算内容身份前。
无目标记忆的状态不新增字段；不同目标的反馈版本独立，迟到反馈不能覆盖较新的反馈。
同一对象每次读取只验一次哈希，不按引用数量重复验证。

这不是截断日志：candidate、反馈、证明文本、预算字段都保留。
新代码受既有实现身份绑定约束，不能绕过旧实验的实现漂移检查直接续跑。

## 真实保存状态验证

实验 015 / Scheduler_Queues / acceptance 000075：

- 原文件：66,370,121 字节；等价去重表示：3,442,831 字节，减少 94.81%。
- 122 个目标引用 1 份 attempt。
- 展开后的完整状态与原状态相等，状态哈希相等，planner_input 完全相等。
- 原实验元数据清单和权威指针哈希不变；没有运行模型或 Isabelle，没有恢复实验。
- 样本文件明确标记为非权威数据，旧 commit_id 不适用于修改后的存储表示。

证据：`reports/regen/incremental-memory-20260930/saved-075/report.json`。
这是一个保存提交的实际测量，不是整段历史的压缩率或线上吞吐测试。

全量回归：1043 项，4 项跳过，其余通过。随后追加的专项测试涵盖无记忆状态、
乱序反馈与独立目标更新；结果见同目录 `focused.log`。

## 第一阶段之后：跨 step 增量提交和磁盘对象库

后续实现与验证现已记录在 [增量实验日志](INCREMENTAL-LOGGING.md)。以下是
第一阶段结束时的剩余工作背景，不再代表当前全部状态。

当前 ProofCommits 仍保存完整状态；源码／原生日志仍嵌入证据。下一格式不能仅改
写入端：repository continuation/fork、sealed reuse、integration、批次恢复、
资源回收及历史快照都存在直接读取完整提交的路径。

后续顺序：统一权威读取接口 → 版本化大对象存储 → delta/checkpoint → 新运行绑定。
不得使现有缓存仅凭提交文件未变就忽略外部对象损坏。对象先持久化、commit 后发布，
必须验证所有引用；checkpoint 不允许跳过此前的接受合法性审计。

后续必测：任意 step 重建等价、历史分叉与 seal/integration、对象缺失／篡改、
发布中断、并发不可变写入、缓存失效、成本守恒，以及冷恢复耗时与峰值内存。
旧实验迁移应输出独立副本并验证；本阶段未改写历史链，也未释放旧实验磁盘。
