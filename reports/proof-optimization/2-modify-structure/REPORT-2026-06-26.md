# seL4 Proof 阶段结构优化：尝试与结论

**日期**: 2026-06-26
**范围**: l4v proof build 的 *结构性* wall-time 优化（不改证明内容、不改硬件）
**基线**: `reports/golden-baseline/BASELINE-2026-05-29.md`（-j2, threads≈16, maxheap 12000, 16 核 / 29GB；总 wall 7h55m）
**结论一句话**: 在固定硬件、不改证明内容、不被上游拒收的前提下，seL4 proof 墙**几乎没有真正的结构优化空间**——墙就是 refinement 数学本身；并行已被压榨到硬件上限；可消除的冗余只有一个 session 且上游拒改。唯一未被证伪的方向（缩关键路径 / flatten）被基建墙挡住。

---

## 0. 问题框架

`-j N` 下，**总 wall ≈ session DAG 的关键路径（最长串行链）**。基线实测验证了这一点：

```
关键链 AInvs(47m)+Refine(80m)+CBaseRefine(36m)+CRefine(168m)+CRefineSyscall(143m)+前缀
  ≈ 7h54m ≈ 总 wall 7h55m
```

推论：**加核 / 加 -j 对总 wall 无用（96% 关键路径绑定）**。最后 5h11m 是 CRefine→CRefineSyscall 背靠背、各自独占运行。结构优化 = 缩短这条串行尾巴。

---

## 1. 尝试一览（按探索顺序）

### 1.1 删 / re-parent CRefineSyscall（唯一的真冗余节点）

- **发现**: `CRefineSyscall`（#2 wall, 8564s）的唯一 theory `Intermediate_C` 只 `imports CRefine.Syscall_C`。因其父是 `CBaseRefine`（非 CRefine），Syscall_C 子树在独立 heap 里**被完整重证一遍**。即使在 `SKIP_DUPLICATED_PROOFS=on` 下也不被守卫（ROOT:89 仅 QUICK_AND_DIRTY）→ 8564s 全是冗余重算。
- **结构签名（可机械检测）**: 入度 0 的叶子 + 其 theory 纯 re-import 一个非祖先 session 的已建子树 + 无独有交付。系统扫描确认：**全 l4v 仅此一个** session 同时满足（重 + 无守卫 + 100% 重算 + 无独有定理）。
- **修法**:
  - 源码 `CRefineSyscall = CRefine +`（消除 8564s，保留 session）→ **上游已明确拒收**（"intentional, exists for memory-constrained dev … very unlikely to accept PRs"，见 `CSTR-2GRAPH-OUTCOME.md:82`）。
  - 本地从 build target 集移除 → 同 −29% wall、零谈判，但丢掉内存受限开发的便利 heap，**仅本地适用、非上游 CI**。
- **裁定**: 真实收益（−2h23m），但 **上游拒改 / 仅本地**。

### 1.2 parent-swap 原理推广（最早 cstr-L1 的延伸）

- **统一原理**: `session S = P + sessions [Q]`，S 的 heap 建在 P 上；从非祖先 Q import 的 theory 会在 S 的 heap 里重证。修正判据：**最小化的是"无守卫的 amplified proof cost"，不是 heap 大小**。
- **扫描结果**: 11 个 re-elaboration site，三道闸门（重 + 无守卫 + 在关键路径）过滤后**只剩 CRefineSyscall**。
- **cstr-L1 复盘**: 其捆绑的 `CBaseRefine = Refine +` swap，目标 Refine 侧已被 `SKIP_DUPLICATED_PROOFS` 守卫（≈free），swap 反而暴露无守卫的 CSpec → 实测 **+17s 回归**。当年 −33% 全来自错误 regime（j=1/skip_dups=off/maxheap），且收益其实只来自 CRefineSyscall 那一半。
- **裁定**: parent-swap 在当前 l4v 上**已被穷尽**，净收益仅 CRefineSyscall 一处。

### 1.3 proof 阶段并行（parallel_proofs / 线程）

- **现状**: threads≈16（auto），`parallel_proofs=1`（默认），-j2。基线 CRefine factor=2.37（cpu/elapsed）→ **16 核空转 ~85%**。
- **裁定**: 见 §2 实验——并行已满，配置调优不算优化。

### 1.4 theory-DAG flatten（维护者唯一愿接 PR 的方向）

- **定位**: Klein 三个开放问题之一，且是 "the only direction the maintainer would consider PRs on"（`CSTR-2GRAPH-OUTCOME.md:139`）。本质：theory A `imports B`，但 A 只用到 C（B 的祖先），把 import 从 B 改指 C → A 不再等 B → 缩关键路径。
- **前序上界**: 4 大 session 的 critical-path 串行 **95-100% 是 arch_split 锯齿**（非 <100 行可翻转）；flatten_simulator ΔCP 约 **10× 虚高**（TcbAcc_R/CSpace_R 标定）。
- **低成本验证尝试**: 想在 CRefine 上跑 `thm_deps` 判断 import 边是否语义必需 → **被基建挡死**：CRefine 增量 heap 虽在，但父 heap（CBaseRefine/CLib/AutoCorres/Refine）被清理，无法加载；重建数小时。可加载的 AInvs/ASpec/BaseRefine 上，依赖 home-theory 提取的 ML API 多版本不稳，3 次未调通。
- **裁定**: **唯一未被证伪的真·结构方向，但被加载墙挡住**，且收益空间有上界。

### 1.5 per-tactic 降本（越界，仅记录）

- command_timings 显示 CRefine 91.5% 时间在 proof tactic（见 §3）。per-tactic（simp only/收紧 lemma 集）是 `direction-a` 已有方向（11/45 命中、单行 14-94%），但**改的是证明内容，出结构范畴**。

## 2. 关键实验：proof 并行是否有 headroom（DRefine 代理）

**方法学**（严格遵循 `.claude/skills/isabelle_prover/references/measurement-tools.md`）: 只用 stock `isabelle build` 自报的 `factor (cpu/elapsed)`，不用 Isa-REPL wall（冷启动+IPC 污染会翻盘）；三配置共用 `--maxheap 20000`、-j1 隔离、同机背靠背；golden DRefine heap/DB 备份后还原。

| 配置 | wall | factor |
|---|---|---|
| baseline（-j2, t≈16, maxheap 12000，DRefine 在中段与同侪抢核） | 21:45 | **1.89** |
| A: -j1, threads=16, pp=1 | 8:50 | **8.09** |
| B: -j1, threads=16, **pp=2** | 8:56 | 8.13 |
| C: -j1, **threads=8**, pp=1 | 8:22 | 6.01 |

**读数**:
1. **parallel_proofs=2 无效**（8.09→8.13，噪声内）。彻底放弃该旋钮。
2. **8 线程是甜点**（维护者问题 #1）：t8 wall 还略优于 t16，核效率 75% vs 51%；>8 线程几乎无收益。baseline 的 -j2×16=32 线程挤 16 核 = 2× 超订（问题 #2）正是 factor 被压到 1.89 的元凶之一。
3. **factor 1.89→8.09 看似巨大，但这是负面结果**：它证明 proof 的并行**本来就全在、且已被压榨到硬件上限**。-j2 是 29GB / 16 核逼出来的（`-j × maxheap ≤ RAM`：-j2×12GB=24GB 适配 29GB），**不是次优失误**。

**结论（关键反转）**: 调 -j/threads/maxheap 是拨 Isabelle **已有旋钮**、随硬件自动 scale 的能力，**不构成优化**。"被节流的并行"并不存在——节流的就是硬件。在更大机器上 seL4 自己就跑满。故此路**无结构优化空间**。

## 3. CRefine 成本的真实拆解（为何无结构杠杆）

从 `CRefine.db` 的 `command_timings`（zstd 压缩，read-only，无需加载 heap）拆解 360m command-elapsed：

| 命令类型 | 占比 |
|---|---|
| **apply** | 78.7% |
| **by** | 12.8% |
| interpretation | 2.5% |
| **crunch** | **0.1%** |
| 全部 setup（crunch+interp+sublocale） | **2.6%** |

- **曾假设"瓶颈在 crunch/locale setup"——数据证伪**（setup 仅 2.6%）。
- **91.5% 是真 proof tactic**；tent-poles 是单步 100-245s 的 `simp(大lemma列表)/clarsimp/vcg/cinit/wp`——**simp work + VCG，不是 classical search**。
- 集中度：top200 步 = 41% of tactic time；≥30s 的 89 步 = 30%。
- **含义**: CRefine 的墙是实打实的证明 tactic 工作，**无 DAG/session/setup 结构杠杆可碰**；唯一能动它的是 per-tactic（出范畴）。

---

## 4. 全盘裁定

| 杠杆类型 | 是否硬件无关 | 是否真·优化 | 状态 |
|---|---|---|---|
| 并行（-j/threads/heap 配置） | 否（随硬件 scale） | ❌ 已有能力，并行已满 | 无空间 |
| 减总工作量（删冗余 session） | 是 | ✅ | 仅 CRefineSyscall，上游拒改 / 本地可用（−29%） |
| 缩关键路径（flatten 边） | 是 | ✅ | **唯一未证伪**，被加载墙挡住，上界有限 |
| per-tactic / 改证明内容 | 是 | — | 出结构范畴（direction-a 已有，收益 modest） |

**最硬结论**: 固定硬件 + 不改证明内容 + 不被上游拒，则 seL4 proof 墙**几乎无真结构优化空间**——墙是 refinement 数学，并行已满，冗余只有一个且不能动。唯一剩下的真·结构杠杆（缩关键路径 / flatten）需要先解决"不重建数小时父链就拿到 CRefine 符号级依赖"的基建问题（如查 build 能否 `export_theory` 把 theory 依赖落进 DB，绕开加载 heap）。

## 5. 复用资产（本轮产出的可重跑工具）

- **command_timings / theory_timings 读取法**: 可从**被剥离父 heap、无法加载**的 session DB 直接读（zstd 解压，不是 lzma）。绕过 REPL init 墙拿 per-command 计时的唯一廉价途径。脚本：`scratchpad/{breakdown,tentpoles,conc,thy_cp}.py`（已归档思路）。
- **re-elaboration site 扫描器**: ROOT 解析 + 祖先链判定 + 三道闸门（非祖先 import / 无 skip 守卫 / 重算占比）。
- **proof 并行 A/B 方法学**: stock build factor、-j1 隔离、heap 一致、golden 备份还原（§2）。
- **不变量**: `-j × maxheap ≤ RAM`（29GB 上 -j2 强制 maxheap≈12GB）；factor=cpu/elapsed 是可复现并行度指标；Isa-REPL wall 不可用于报告数字。
