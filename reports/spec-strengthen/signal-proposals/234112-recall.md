## Structural signature
For `form hoare` lemmas, a win occurs when the proof opens by unfolding the **operation's own definition** (`<op>_def`) and then uses `hoare_pre` (or `hoare_pre_imp`) as a simple precondition-weakening step, followed by a pure wp/wpc/wpsimp/clarsimp chain — with no backward-reasoning tactics (`drule`, `frule`), no `strengthen`, no `hoare_gen_asm`, and no `rule_tac`. This pattern signals that the proof is entirely forward-driven through the operation's body: each sub-operation discharges its own preconditions via registered wp lemmas, so any bundled premise (e.g., `invs`) in the outer precondition was over-specified. Dropped premises were never needed beyond what the wp lemmas consume directly.

## Why it's novel (not an existing signal)
The six existing signals penalise or ignore these cases: signal 4 (write-op demotion) actively demotes wins 2–3 because invoke_cnode is a write-op; signal 2 (differential) cannot promote them because there may be no other conjunct visibly consumed in the proof text; signals 1/3/5/6 are silent here. This signal is a *proof-structure boost* — it fires on the presence of a specific compositional proof idiom (op-def unfolding + hoare_pre weakening + pure wp chain) rather than on premise-presence/absence or op class, allowing it to recover write-op wins that signal 4 wrongly demoted.

## Expected effect
Boosts wins 2–5 (invoke_cnode_valid_pdpt_objs_no_invs, invoke_cnode_valid_pdpt_objs_min, get_simple_ko_valid_obj', decode_unbind_notification_wf_strong): all four are hoare-form, all open with `simp add: <op>_def`, all use `hoare_pre`/`hoare_pre_imp`, and none use the excluded tactics. Win 1 (form impl) is missed, which is acceptable. All 20 losses are spared: losses 3–5 lack `hoare_pre`; loss 6 has `strengthen`; losses 7–8 lack `hoare_pre`; loss 14 unfolds `invs_def` instead of `cap_insert_def`; loss 15 has `cap_insert_def` but no `hoare_pre`; loss 18 has `rule_tac`; losses 19–20 have no `hoare_pre`; all impl-form and unknown-op losses are excluded by the form/op guards.

## Proposed predicate (for calibration; review before promoting)
```python
def proposed_signal(feat):
    form  = feat.get('form', '')
    proof = feat.get('proof', '')
    op    = (feat.get('op') or '').strip()

    # Only applies to Hoare triples with a known operation name
    if form != 'hoare':
        return False
    if not op or 'unknown' in op.lower():
        return False

    # Proof must unfold the operation's *own* definition
    if (op + '_def') not in proof:
        return False

    # Proof must use hoare_pre / hoare_pre_imp for precondition weakening
    if 'hoare_pre' not in proof:
        return False

    # Must not use complex backward-reasoning or non-standard proof structure
    exclusions = ['rule_tac', 'strengthen', 'hoare_gen_asm', 'drule', 'frule']
    if any(excl in proof for excl in exclusions):
        return False

    return True
```
