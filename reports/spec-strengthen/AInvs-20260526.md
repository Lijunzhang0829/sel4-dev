### [A] CSpace_AI.thy — `get_cap_wellformed` (lines 130-134)

| Field | Value |
|---|---|
| Lemma | `get_cap_wellformed` |
| Before | `\<lbrace>valid_objs\<rbrace> get_cap slot \<lbrace>\<lambda>cap s. wellformed_cap cap\<rbrace>` |
| After  | `\<lbrace>valid_objs\<rbrace> get_cap slot \<lbrace>\<lambda>cap s. valid_cap cap s\<rbrace>` |
| Proof before | `apply (rule hoare_strengthen_post, rule get_cap_valid)` + `apply (simp add: valid_cap_def2)` + `done` |
| Proof after  | `by (rule get_cap_valid)` |
| Patch file | `logs/spec-strengthen-CSpace_AI-A-get_cap_wellformed-20260524.patch` |

**Why strictly stronger.** `valid_cap_def2` says
`s \<turnstile> c \<equiv> cap_aligned c \<and> wellformed_cap c \<and> valid_cap_ref c s`,
so `valid_cap cap s` adds `cap_aligned cap` and `valid_cap_ref cap s` on
top of `wellformed_cap cap`. Same precondition.

**Why proof simplifies.** `get_cap_valid` (line 124) already states the
strong form directly. The old proof used `hoare_strengthen_post` to weaken
to `wellformed_cap` — that step now disappears.

**Why the weak form was there.** Historical: `wellformed_cap` is the
purely-structural property (no state reference); used to be the
convenient unification target for goals that didn't have an `s`. Today
`valid_cap` is the dominant `[wp]` rule; the weak alias is unused.

### [B] CSpace_AI.thy — `set_cdt_cdt_update` (new, after line 428)

| Field | Value |
|---|---|
| Lemma | `set_cdt_cdt_update` (NEW) |
| Statement | `\<lbrace>\<top>\<rbrace> set_cdt t \<lbrace>\<lambda>_ s. cdt s = t\<rbrace>` |
| Proof | `by (wpsimp simp: set_cdt_def)` |
| Patch file | `logs/spec-strengthen-CSpace_AI-B-set_cdt_cdt_update-20260524.patch` |

**What this enables.** Previously the only `set_cdt` lemmas were
preservation-shaped (`set_cdt_valid_pspace`, `set_cdt_valid_objs`,
`set_cdt_valid_ioc`, …) — none of them tell a consumer "after `set_cdt t`,
the `cdt` field equals `t`". Any downstream proof needing that fact had
to manually unfold `set_cdt_def`. Now `wp set_cdt_cdt_update` discharges
it directly.

**Definition reference** (spec/abstract/CSpaceAcc_A.thy:81-87):
```isabelle
definition set_cdt :: "cdt \<Rightarrow> (unit,'z::state_ext) s_monad" where
  "set_cdt t \<equiv> do s \<leftarrow> get; put $ s\<lparr>cdt := t\<rparr> od"
```
The new lemma is the direct functional reading of this definition.

## Negative result: `set_cdt_invs` (Pattern E)

Attempted to introduce a new compound `set_cdt_invs : \<lbrace>invs and valid_mdb (s\<lparr>cdt := m\<rparr>)\<rbrace> set_cdt m \<lbrace>\<lambda>_. invs\<rbrace>` since `set_cdt` has 85 callsites and no existing compound `_invs` lemma (Pattern E rationale: enables `wp set_cdt_invs` to collapse what currently are 5+ separate preservation `wp` rules).

**5 proof variants attempted, all failed:**

| # | Tactic | Result |
|---|---|---|
| v1 | `apply (simp add: invs_def valid_state_def valid_pspace_def); rule hoare_pre; wp set_cdt_valid_pspace set_cdt_valid_objs set_cdt_cur valid_irq_node_typ; clarsimp simp: valid_mdb_def cur_tcb_def set_cdt_def` | FAILED — goal left as unfolded monad |
| v2 | `simp add: set_cdt_def; wp; clarsimp simp: invs_def valid_state_def valid_pspace_def cur_tcb_def` | FAILED — many arch invariants unhandled |
| v3 | + simp lemmas for arch defs | FAILED — `valid_arch_state_def` is locale-scoped, not directly accessible |
| v4 | `auto simp: invs_def valid_state_def valid_pspace_def cur_tcb_def` | FAILED — auto timed out |
| v5 | `simp add: invs_def valid_state_def; rule hoare_pre; wp [7 preservation lemmas]; clarsimp` | FAILED — "Unification bound exceeded" on conjunctive postcondition |

**Root cause**: `set_cdt` lacks `[wp]` preservation rules for the architecture-specific components of `invs` (`valid_arch_state`, `valid_machine_state`, `valid_vspace_objs`, `valid_arch_caps`, `valid_global_objs`, `valid_kernel_mappings`, `equal_kernel_mappings`, `valid_asid_map`, `valid_global_vspace_mappings`, `pspace_in_kernel_window`, `cap_refs_in_kernel_window`, `pspace_respects_device_region`, `cap_refs_respects_device_region`, `valid_irq_handlers`, `valid_ioports`, `only_idle`, `valid_global_refs`). To make `set_cdt_invs` work, these missing preservation rules need to be added first — likely via `crunches` macros invoking `valid_*_lift` patterns that consume `set_cdt_typ_at`.

**Lesson learned**: Pattern E heuristic was too optimistic. An op missing `_invs` may not have all the sub-preservation `[wp]` rules in place. The scanner should also check whether each component of `invs` has a `set_X_<component>[wp]` rule before listing `set_X` as a Pattern E candidate. This refinement is added to the skill's `TODO`.
