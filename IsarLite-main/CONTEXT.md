## YXML
YXML is just a simplified XML format:
`<name attribute=value . . .> ... </name>` is represented as
`XYnameYattribute=value. . .X ... XYX`

## Isabelle native build
Artifacts generated by `isabelle build ...` will be placed in `$HOME/.isabelle/Isabelle202*/heaps/polyml-*.*.*_x86_64-linux`. Here is a typical file structure of it:
```
├── HOL
├── Pure
└── log
    ├── HOL.db
    ├── HOL.gz
    ├── Pure.db
    └── Pure.gz
```
We call the generated <Session>.db files "session db"s.

## Isabelle version pitfalls
Isabelle ML files demand strict versioning. For example, MLs accepted by Isabelle2025 may not be accepted by Isabelle2024 AND later versions like Isabelle2025-1.

In this project, we focus on Isabelle2025 only. Porting to other versions are deferred to future work.


## Timeout, Retrying and Dead Loop handling

Pcocessing a command may take any long time. 

Also, isabelle couldn't tell whether a command would terminate (undecidable!).

The following ARE a subset of the possible cases need consideration:

1. the request does takes the ml server a long time to handle and it terminates. no
intermediate outputs.
1. same as 1 but show intermediate outputs like sledgehammer
2. processing the command results in a dead loop that does not terminate. no output.
however, the ide would highlight the command span indicating that it is still processing.
for our cli case, the cli should print a message showing that isabelle is still processing
every given interval (provided as a parameter), and an optional timeout could make the
cli exit(1) with a timeout error. if no timeout, the cli should also stay dead loop.
